# 系统架构

## 架构原则

- 账务核心不依赖 Android、Desktop UI、网络、同步或 AI。
- 业务规则通过明确接口访问存储、文件和平台能力。
- 解析器、匹配器和约束求解器只产生候选，不直接写入正式账本。
- 平台模块负责系统权限和交互，不在界面层修补账务规则。

## 逻辑分层

1. 领域层：金额、账户、交易、分录、证据和不变量。
2. 应用层：用例、事务边界、确认流程和端口。
3. 数据与导入层：持久化、来源标准化、去重、匹配和审计。
4. 平台层：Android 与 Desktop 的权限、文件、通知和系统入口。
5. 表现层：平台 UI、状态展示和用户操作。

## 基本数据流

手工输入或来源文件先形成来源事实与候选；用户确认后创建或替换正式交易和分录；余额与报表从有效分录计算；对账记录独立关联来源证据与真实账户分录。
