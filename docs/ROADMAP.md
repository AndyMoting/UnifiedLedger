# 路线图

## 阶段 1：正式文档与规则迁移

建立权威文档，迁移已确认决定与通用账务规则，并完成结构和隐私检查。

完成条件：九份正式文档职责明确，决定编号可追溯，当前状态具有唯一下一步。

## 阶段 2：黄金测试冻结

为匿名规则场景和本地真实来源场景写出完整预期交易、分录、余额、统计与对账结果。

完成条件：核心场景能够逐交易和逐分录比较，不只比较最终总额。

## 阶段 3：共享核心验证

使用纯 Kotlin/Kotlin Multiplatform 实现已冻结的领域模型和用例，并与 Python 基线比较。

完成条件：黄金场景通过，核心不依赖平台、网络、同步或 AI。

## 阶段 4：导入与对账闭环

建立来源适配、标准化、去重、候选确认、证据匹配和差异处理。

完成条件：支持的来源能够从导入走到正式账目与可解释对账状态。

## 阶段 5：双端最小外壳

建立 Android 与 Desktop 可运行外壳，持续编译并调用同一业务核心。

完成条件：两端可以打开本地测试账本并运行共享用例。

## 后续阶段

依次完善 Android 日常工作流、Desktop 批量工作台、可选同步和 AI 扩展。后续能力不得破坏更早阶段的不变量和离线可用性。
