# P8-01 桌面批量导入入口与流程设计（阶段 8 第一件）

状态：proposed
Revision: v0.2（2026-11-05 修订：补齐批交付形状、失败边界与可判定的验收夹具；依据 Lead 自审 BLOCKER-1 / MAJOR-2 / MINOR-3）

**依据：**

- `docs/ROADMAP.md:76-81`：阶段 8 的完成条件是「用户可对一批来源完成导入、去重、审核、入账和差异处理，并获得可追溯结果」。
- 现状勘察（本批实读）：
  - `desktop-app/.../ImportFilePick.kt:98-119`：桌面选择器是 **`JFileChooser.FILES_ONLY` + `isMultiSelectionEnabled = false`**，返回 `File?` —— **单文件单选**。
  - 已有的桌面组装根：`DesktopImportReviewCompositionRootTest`、`DesktopImportBatchConfirmationCompositionRootTest`、`DesktopImportFilePickPortTest` 三个套件在位，说明**单文件的审核与批量确认链路已经可用**。
  - Android 侧已有成熟的多文件语义可借用：分享导入的多流、`ImportFilePickResultChannel`、以及 A-05 整链验证过的「一次接洽 + 逐条已接治」回执。

**缺口（只列真的缺的）：**

1. **选择器只能选一个文件**（这是本设计的核心动机）；
2. 没有「一批来源」的队列概念：谁先谁后、某个文件失败时其余怎么办；
3. 跨文件的重复候选没有统一入口（现有重复组卡是**批内**语义）；
4. 没有「整批导入结果」的汇总视图（现有的是**批内逐项**结果）。

**设计（P8-01a 选择器与队列）：**

1. **端口形状**：新增 `PickedImportFiles(files: List<File>, source: PickSource)`，`PickSource = SELECTION | DIRECTORY_SUMMARY`；`DesktopImportFilePickPort` 增加一个返回 `PickedImportFiles` 的入口，**保留**现有的单文件入口不动（Compose 侧已有调用点，改签名会把风险扩散到不可见的地方）。
2. **选择模式**：选择器改为 `FILES_ONLY` + **多选开启**；目录选择作为**第二个**入口（`DIRECTORY_SUMMARY`：选目录 → 只取顶层 `*.csv/*.xls(x)`，不递归，避免误吞用户整棵树）。
3. **队列语义与交付形状（v0.2 补齐）**：一批文件**按路径字典序**顺序处理，一次只跑一个 intake。
   - 现有点击通道 `ImportFilePickResultChannel.deliver(result)` 是**一次一个**的交付（`P503ImportReview.kt:334-346`，桌面端 `Main.kt:933-938` 直接接上）。
     因此批次**不能**通过循环 `deliver` N 次来实现——那会让宿主对每个结果各起一次接洽，与 single-flight 自相矛盾。
   - 规格要求**一次性批量交付**：`ImportFileBatchPicked(files: List<File>, source: PickSource)` 作为一个新的通道消息，
     由宿主在内部**按序扇出**（第 k 个文件接洽完成后再起第 k+1 个）。
   - **批内重入**：扇出期间用户再次点击导入 → **拒绝并给可见 Busy 提示**（沿用分享导入的「Busy 可见、不静默」纪律），
     不排队、不打断正在进行的那个文件。
4. **失败隔离（v0.2 补齐边界）**：文件级失败分三类并各自有文案——读取失败（打不开/权限）、解析失败（格式不认）、接洽拒绝（域内拒绝）；**三类都不回滚整批**，且：
   - **已接洽成功的条目保留**（接洽是逐条事务，不因后续文件失败而撤销）；
   - **重选同一个文件按等价重放处理**（既有 request identity 语义），不会产生重复候选；
   - 失败文件的条目**不进**「整批汇总」的新增计数，但**进**该文件的解析/接洽拒绝计数。

**设计（P8-01b 跨文件去重与汇总）：**

5. **跨文件重复**：新增「整批重复视图」入口，把本批内所有会话的重复候选按 `EXACT_BUSINESS_TUPLE` 聚合；**不**改现有批内重复组卡的语义（D-280 体系），只在上面加一层跨会话视图。
6. **整批汇总**：一份可追溯结果 = 文件数 / 每文件四类计数（新增、等价重放、解析拒绝、接洽拒绝）/ 跨文件重复数 / 入账数，落在一个只读视图里，可导出文本。

**验收（实现批必须逐条给出读数）：**

1. 一次选 3 个 CSV → 接洽按字典序执行、三个摘要都在、某个故意坏掉的文件只影响它自己；
2. 目录选择只取顶层、不递归（用一个含子目录的夹具证明）；
3. 跨文件重复视图能聚合出「同一业务元组出现在两个文件」的情形，夹具与期望值固定：两个文件各含**同一业务元组的 1 条**记录 →
   跨文件重复 = **1 组 / 2 条候选**（判定按这两个数，不按「看起来有重复」）；
4. 整批汇总的四类计数与权威库逐项相等；
5. 全流程零崩溃；关闭/重开应用后结果不丢（只读历史）。

**非目标：**

- 不做目录递归、不做通配符匹配、不做压缩包；
- 不改既有单文件导入的 UI 与语义；
- 不做后台/定时导入（阶段 8 范围内仍是显式用户动作）；
- 不动 Android 侧任何导入行为。

**风险：**

- 选择器从单选变多选会改变既有 `DesktopImportFilePickPortTest` 的假设，实现批要同步更新断言而不是让它「恰好还是绿的」；
- 顺序处理在大批文件时可能显得慢；本设计**先正确后快**，并行化留作独立决定（与 A-PERF 的教训一致：先量再优化）。
