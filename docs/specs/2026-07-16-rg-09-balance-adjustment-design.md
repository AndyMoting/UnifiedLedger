# RG-09 目标余额调整与替代设计

## 1. 目的

本设计冻结公开匿名黄金场景 `RG-09` v1 的目标余额调整答案。它验证目标时点重放、明确确认、专用调整权益、统计隔离、预览过期、真实交易部分解释、同目标时点反向调整、证据职责、核验语义、完整状态、引用完整性和按输入幂等。

本设计只规定可观察的账务、报告和状态行为，不固定数据库、界面或平台实现。

## 2. 固定数据与时间

场景使用完全合成的数据：

| 项目 | 固定值 |
| --- | --- |
| 场景 ID | `RG-09` |
| 场景级别 | `core_required` |
| 规则版本 | `1` |
| 时区 | `Asia/Shanghai` |
| 币种与精度 | `CNY`，两位小数 |
| 目标账户 | `asset-a`，自有真实资产账户 A |
| 转出账户 | `asset-b`，自有真实资产账户 B |
| 调整对手账户 | `equity-balance-adjustments`，系统管理且隐藏的“余额调整”权益账户 |
| 目标观察时点 | `2026-01-31T23:59:59+08:00` |
| 目标时点重放余额 | `100.00 CNY` |
| 目标余额 | `130.00 CNY` |
| 原始差额 | `+30.00 CNY` |
| 后发现真实交易 | `2026-01-20T12:00:00+08:00`，资产 B 向资产 A 转账 `20.00 CNY` |
| 发现时间 | `2026-02-10T17:30:00+08:00` |
| 解释确认时间 | `2026-02-10T18:05:00+08:00` |

期初平衡交易建立资产 A `100.00`、资产 B `50.00` 和期初权益 `-150.00`。所有状态都从期初交易累计重放，不直接覆盖余额。目标观察时间、真实交易时间、发现时间和确认时间是四种不同事实，不能互相替代。

## 3. 预览与过期校验

目标余额预览保存目标观察、来源证据和调整候选，并显示重放余额 `100.00`、目标余额 `130.00` 和差额 `+30.00`。预览不创建正式交易、分录、版本或调整，也不改变余额、报告或核验。

候选保存目标时点有效分录集合的稳定指纹。确认时必须重新重放；若目标时点或更早的有效分录已变化，旧预览原子拒绝。例如后来补入目标时点以前的 `5.00` 内部转账后，重放余额成为 `105.00`，旧差额 `30.00` 失效，系统返回新差额 `25.00` 并要求重新明确确认。拒绝本身不保存新的调整或确认历史。

## 4. 调整交易与专用权益

明确确认未过期的 `+30.00` 差额后，在目标观察时点创建：

| 分录账户 | 金额 |
| --- | ---: |
| 资产账户 A | `+30.00 CNY` |
| 余额调整权益 | `-30.00 CNY` |

两条分录逐币种平衡。对手账户只能是专用余额调整权益，不能使用普通收入、费用、期初权益、暂记资产或悬空账户。调整是正式可重放交易，不是余额字段覆盖。

调整后资产 A 为 `130.00`，净资产增加 `30.00`。普通收入、普通费用、消费、预算、分类统计、现金流入和现金流出全部为 `0.00`。独立调整报告和总净资产变化记录 `+30.00`。

## 5. 正负差额与零差额

差额定义为“目标余额减重放余额”。正差额增加目标资产并减少调整权益；负差额减少目标资产并增加调整权益。负差额边界例为重放 `100.00`、目标 `70.00`、差额 `-30.00`，分录是资产 A `-30.00`、调整权益 `+30.00`。

零差额保存目标观察、来源证据和类型明确的观察链接，创建交易、分录和版本的数量均为零。系统不得伪造零金额调整交易。

## 6. 真实交易与部分解释

后来用户确认此前遗漏的真实账户互转实际发生于 `2026-01-20T12:00:00+08:00`：

| 分录账户 | 金额 |
| --- | ---: |
| 资产账户 A | `+20.00 CNY` |
| 资产账户 B | `-20.00 CNY` |

真实交易保持自己的实际时间、账户互转身份和正常转账报告。它不因为发现较晚而改用发现日或确认日，也不被伪装成调整、收入或费用。内部转账本金为 `20.00`，普通收入、费用、消费、预算、分类和对外现金流仍为零。

用户另外在独立操作中明确确认该交易向原 `+30.00` 差额解释 `20.00`。真实交易确认只创建正式转账、版本和确认历史；解释分配确认只创建分配、反向调整和审计链接。两次操作都明确提供目标账户、实际发生时间、币种、金额、解释金额和所需布尔确认；一笔已经正式存在的真实交易也不能仅凭匹配结果自动链接。

## 7. 分配与反向调整

解释确认必须在一个原子操作中创建稳定分配和恰好一笔反向调整。反向调整在原目标观察时点生效：

| 分录账户 | 金额 |
| --- | ---: |
| 资产账户 A | `-20.00 CNY` |
| 余额调整权益 | `+20.00 CNY` |

因此目标时点累计结果为：期初资产 A `100.00`，真实转入 `+20.00`，原调整 `+30.00`，反向调整 `-20.00`，最终仍为目标 `130.00`。资产 B 为 `30.00`。专用调整权益净额为 `-10.00`，表示仍有 `10.00` 未解释差额；累计净资产变化为 `+10.00`。

反向调整不能放到发现日或确认日，否则会在目标时点到确认日之间重复计算真实交易和原调整。发现时间和确认时间只进入分配与审计历史。

## 8. 状态与分配上限

调整状态只由不可变分配累计推导；第二笔真实交易可以解释剩余 `10.00`，但主部分解释状态仍保留为独立历史：

| 已解释 | 剩余 | 状态 |
| ---: | ---: | --- |
| `0.00` | `30.00` | `open` |
| `20.00` | `10.00` | `partially_explained` |
| `30.00` | `0.00` | `fully_explained` |

每个分配必须与原差额方向一致，引用同一目标账户和币种，其真实交易时间不得晚于目标观察时点。累计解释绝对值不得超过剩余差额。主路径剩余 `10.00` 时申请解释 `11.00` 必须整项拒绝；不能自动截为 `10.00`，不能创建部分分配或反向调整，也不能猜测另一个经济事件。

## 9. 导入、匹配与明确触发

导入可以产生遗漏真实交易候选和建议解释链接。候选保存来源、置信度和建议值，但必须保持 `pending_confirmation`，直到用户明确确认以下全部事实：

1. 精确真实交易。
2. 精确目标账户。
3. 真实发生时间。
4. 币种。
5. 解释分配金额。

任一事实缺失都保留完整导入基线，不创建交易、分录、版本、分配、反向调整或确认，也不改变余额、报告或核验。置信度无论多高都不能触发自动反向调整。候选接收的来源、证据和候选增量与正式效果分别记录，不能用一个全零向量掩盖已保存的接收实体。

## 10. 证据与核验

目标余额来源使用 `target_balance_observation` 职责，只链接精确目标观察。真实转账的两个账户来源分别使用 `real_account_posting` 职责，只核对资产 A 和资产 B 的精确真实分录。调整、真实解释交易和反向调整使用 `adjustment_transaction`、`explanation_transaction` 和 `allocation_reversal` 审计职责链接到同一分配。所有链接目标必须存在且类型正确，不允许悬空或跨类型引用。

原调整使账户数值达到目标，但剩余调整为 `30.00` 时，状态是 `balanced_with_unexplained_adjustment`。部分解释后即使真实转账两条分录都已匹配，剩余 `10.00` 仍保持该状态。第二笔真实转账确认和第二笔解释分配确认分别保存完整成功操作；分配使剩余调整归零后，规范状态先成为 `fully_explained` 加 `evidence_incomplete`，四条真实资产分录均保持待证据。随后四个账户证据来源分别通过独立成功操作依次建立精确链接，前三个结果仍为 `evidence_incomplete`，只有第四个也是最后一个缺失链接完成后才进入 `fully_reconciled`。核验和证据变化不改变余额或报告。

## 11. 不可变历史与幂等

原调整交易和版本、目标观察、来源证据、真实交易、解释分配、反向调整、确认及历史都使用稳定 ID 并追加保存。解释只能追加分配、反向调整和派生状态历史；原始差额、原交易、原分录、原目标和旧历史不能删除或修改。每个确认分配恰好有一笔反向调整。

预览请求、调整确认、目标观察来源、真实转账请求、解释确认、导入来源、两端账户证据和零差额观察分别定义幂等键。每个输入重试都保存自己的完整命名操作前基线、逐字段相同的完整结果状态、返回的稳定实体 ID、零正式增量和零接收增量。相同键携带冲突内容时拒绝为 `idempotency_key_conflict`。

所有无效目标、过期预览、错误账户或币种、错误调整权益、错误解释方向、目标以后交易、超额分配、猜测链接和导入缺失确认都保存完整操作前状态与完整结果状态。结果必须与基线逐字段相同，并分别列出精确正式增量和接收增量。

## 12. 完整状态与验证

机器答案保存期初、已预览、已确认调整、独立真实转账确认、独立解释链接确认、预览过期变更、部分解释、导入待确认、导入真实转账确认、导入解释链接确认、第二笔真实转账确认、零剩余但证据不完整、四个逐步证据链接结果、完全解释且完全核验和零差额观察等完整规范状态。每个状态包含完整交易与分录、版本、调整及历史、分配、候选、确认、观察、来源、证据、证据链接、审计链接、余额、报告和核验。第二笔真实交易确认、第二笔解释分配确认和每条导致完全核验的真实分录证据链接均有独立输入、命名完整前置基线、接受状态、精确正式与接收增量、完整结果状态和按输入幂等结果。

测试从期初交易累计重放每个状态，逐币种检查平衡和余额，并从交易类型与分配独立推导逐期及累计报告。引用检查遍历全部规范状态、成功结果、失败基线、失败结果和幂等重试状态；嵌套变异测试覆盖版本归属、调整目标、分配的调整与交易引用、观察账户类型、证据来源和职责、审计链接目标以及确认请求。

## 13. 校验与范围

目标金额和正式金额必须使用精确两位十进制，不接受二进制浮点数。目标必须是已知、自有、真实金融资产账户，时间必须带 `Asia/Shanghai` 对应时区，币种必须是 `CNY`。专用调整权益必须使用固定系统角色。解释必须满足方向、账户、币种、时间和剩余上限；任何失败都原子保持完整状态。

v1 不覆盖多账户目标、负债目标、外汇、并发调整、真实收入或费用解释，以及超出基础边界的修正流程。负差额只冻结对称方向规则；公开主路径只包含一个正差额目标账户和一笔部分解释的真实账户互转。

## 14. 验收标准

`RG-09` v1 只有同时满足以下条件才通过：

- 预览显示重放 `100.00`、目标 `130.00`、差额 `+30.00`，明确确认前零正式影响。
- 调整交易在目标观察时点形成资产 A `+30.00` 与专用调整权益 `-30.00`，不覆盖余额。
- 调整增加净资产 `30.00`，普通收支、消费、预算、分类和现金流全部为零。
- 过期预览原子拒绝并返回重算差额，等待新的明确确认。
- 后发现真实转账按 `2026-01-20` 入账，解释确认在原目标时点创建资产 A `-20.00` 与调整权益 `+20.00` 的唯一反向调整。
- 部分解释后资产 A 仍为 `130.00`，剩余调整为 `10.00`，状态为 `partially_explained`，累计净资产变化为 `10.00`。
- 方向、账户、币种、时间和累计上限全部校验；超额、猜测链接和冲突幂等键整项拒绝。
- 零差额保存观察和证据但不创建零交易；负差额方向与正差额严格对称。
- 导入和匹配只能提出候选，全部精确事实与解释分配明确确认前不触发正式交易或反向调整。
- 数值一致但仍有未解释调整时不得完全核验；证据职责和审计职责目标明确且无悬空引用。
- 所有实体和历史不可变；全部规范状态可累计重放，全部无效、不完整和重试操作冻结完整基线、完整结果及精确增量。
