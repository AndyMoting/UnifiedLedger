# RG-08 借贷与结算设计

## 1. 目的

本设计冻结公开匿名黄金场景 `RG-08` v1 的借出与收款答案。它验证个人级借贷本金位置、稳定行为与往来对象身份、借出和收款的现金口径、实际利息收入、本金上限、导入确认、证据职责、分录级对账、完整历史、镜像合并和幂等结果。

本设计只规定可观察的账务、报告和状态行为，不固定数据库、界面或平台实现。四种行为代码全部冻结，但主经济路径只覆盖借出与收款；借入和还款的详细生命周期不在本场景内。

## 2. 固定数据与独立基线

场景使用完全合成的数据：

| 项目 | 固定值 |
| --- | --- |
| 场景 ID | `RG-08` |
| 场景级别 | `core_required` |
| 规则版本 | `1` |
| 时区 | `Asia/Shanghai` |
| 币种与精度 | `CNY`，两位小数 |
| 往来对象 | `counterparty-rg08`，稳定个人身份 |
| 借贷位置 | `lending-position-rg08`，个人级应收净本金 |
| 借出账户 | `asset-bank-a`，资产账户 A |
| 收款账户 | `asset-wallet-b`，资产账户 B |
| 应收账户 | `receivable-counterparty-rg08` |
| 利息分类 | `income-category-interest-rg08` |
| 利息账户 | `income-interest-rg08` |
| 借出 | `100.00 CNY`，`2026-01-10T09:00:00+08:00` |
| 收款 | `45.00 CNY`，`2026-02-15T14:30:00+08:00` |
| 收款拆分 | 本金 `40.00`、利息 `5.00`、费用 `0.00` |

手工路径、导入路径和本金上限路径从各自命名基线运行，不互相累计。期初平衡交易建立资产 A `1000.00 CNY`、资产 B `200.00 CNY` 和期初权益 `-1200.00 CNY`；测试通过完整交易重放余额，不直接覆盖余额。

## 3. 稳定行为与身份

借贷行为代码固定为 `borrow`、`lend`、`collect` 和 `repay`，不能依赖显示名称。借出与收款都引用稳定 `counterparty_id`；姓名、别名和金融账户不承担身份主键职责。

首版每个往来对象只有一个个人级净本金位置。位置记录币种、应收账户、当前本金和按顺序追加的本金事件历史。收款链接位置，不链接某一份合同，也不把本金分配到某笔原始借出。往来对象改名对位置、交易、余额和报告产生零影响；重复对象合并必须是后续定义的明确可审计操作。

## 4. 借出本金

用户明确保存借出 `100.00 CNY` 后创建一笔平衡交易：

| 分录账户 | 金额 |
| --- | ---: |
| 往来对象应收资产 | `+100.00 CNY` |
| 资产账户 A | `-100.00 CNY` |

借出后资产 A 为 `900.00`、资产 B 为 `200.00`、应收本金为 `100.00`。当期借贷本金现金流出为 `100.00`，总现金流出为 `100.00`；消费、费用、收入和净资产变化均为零。资产 A 分录独立参与对账，应收分录不使用外部金融账户对账。

## 5. 预计利息

借出可以保存预计利息 `8.00 CNY` 等提醒或约定元数据，但首版不确认应计收益。预计利息及尚未实际收到的利息不创建交易、分录或版本，不改变应收本金、余额、现金流、收入、净资产或对账。

预计利息也不能用于自动解释后续银行入账。即使银行入账总额与“本金加预计利息”一致，仍必须由用户明确确认本金、利息和费用拆分。

## 6. 实际收款

用户在 `2026-02-15T18:00:00+08:00` 明确确认资产 B 已于当天 `14:30` 收到 `45.00 CNY`，并明确拆分本金 `40.00`、利息 `5.00`、费用 `0.00`。系统创建独立结算和一笔平衡交易：

| 分录账户 | 金额 |
| --- | ---: |
| 资产账户 B | `+45.00 CNY` |
| 往来对象应收资产 | `-40.00 CNY` |
| 精确利息收入账户 | `-5.00 CNY` |

结算、交易、本金组成、利息组成和零费用组成均有稳定 ID。零费用组成保留身份但不伪造零金额分录。`RG-08` v1 要求费用被明确确认为 `0.00`；负数费用与任何正数非零费用均拒绝，不推断费用的资金方向、账户或报告语义。结算引用个人级位置，`allocated_lend_transaction_id` 为 `null`。

收款后资产 A 为 `900.00`、资产 B 为 `245.00`、应收本金为 `60.00`、利息收入账户为 `-5.00`。只有本金减少位置余额；实际利息不改变本金。

## 7. 报告口径

借出期记录借贷本金现金流出 `100.00`，不记录消费、费用、收入或净资产变化。收款期记录借贷本金现金流入 `40.00`、利息现金流入 `5.00` 和总现金流入 `45.00`；普通利息收入和普通收入均为 `5.00`，净资产增加 `5.00`，消费与费用均为零。

累计报告保持借贷本金现金流出 `100.00`、本金现金流入 `40.00`、利息现金流入 `5.00`、总现金流入 `45.00`、普通利息收入 `5.00`、消费 `0.00` 和净资产增加 `5.00`。报告使用实际支付或到账时间；确认时间不回写资金期间。

## 8. 本金上限与原子拒绝

结算前应收本金为 `100.00` 时，本金 `100.00` 加实际利息 `5.00` 的总收款 `105.00` 可以接受，并把位置准确结清到 `0.00`。该成功输入必须显式携带行为、稳定往来对象、到账账户、总额、本金、利息、`0.00` 费用、精确利息分类 ID、币种、实际到账时间和确认时间；即使利息为 `0.00` 也不能省略精确利息分类。任何字段都不能从既有位置、名称、预计利息或系统默认值推断。本金不得超过未结余额，也不得跨越零点。

若尝试把总收款 `106.00` 拆为本金 `101.00`、利息 `5.00`，整笔分配拒绝。系统不得自动只接受本金 `100.00`，已分配本金保持 `0.00`，全部 `106.00` 保持 `pending_explicit_reallocation`。用户必须明确重新拆分，或另行确认独立的借入、普通收款等真实经济事件；系统不能猜测收入、借贷行为或清算分录。

## 9. 手工与导入确认

手工保存只有在行为、稳定往来对象、到账账户、本金、利息与费用以及实际到账时间均明确填写时才构成确认。

导入银行入账先创建 `pending_confirmation` 候选。来源可以提出总额 `45.00`、资产 B 和入账时间，但候选的本金和利息保持未知。候选逐项列出六组待确认事实：

1. 借贷行为代码。
2. 稳定往来对象 ID。
3. 到账资产账户。
4. 本金金额。
5. 利息与费用金额。
6. 实际到账时间。

任一事实缺失都保持完整导入候选基线，不创建交易、分录、位置事件、结算、组成、版本或确认历史，也不改变余额、报告或对账。六种缺失情况分别使用稳定且字段专属的失败原因，不能合并为一个含糊错误。名称匹配不能确认往来对象，预计利息不能确认拆分。六组事实全部明确确认后，导入路径产生与手工路径相同的经济结果，但保留自己的稳定实体 ID、来源、候选和确认历史。

导入接收本身会保存一条候选、一条候选历史、两条来源记录、两条证据和一条关系证据链接；这些是精确的接收实体增量，不是正式账务效果。候选待确认期间，新增位置事件、结算、组成、正式交易、分录和版本均为零，余额、报告、消费、现金流、收入与对账变化也均为零。机器答案分别冻结这两个向量，不能用一个全零计数掩盖已经保存的接收实体。

## 10. 账户、金额与分类校验

首版只接受同一 `CNY` 币种。借出资金账户和收款到账账户必须是已知、由用户持有的真实资产账户；未知、不属于用户或非金融账户均拒绝。往来对象必须已知，行为必须是冻结的四种代码之一，收款主路径必须使用 `collect`。

总额必须为正的精确两位十进制字符串，不接受二进制浮点数。本金和利息不得为负，费用必须严格等于 `0.00`，组成合计必须严格等于总额。负数费用使用 `fee_must_be_zero_in_rg08_v1` 拒绝；正数非零费用使用 `nonzero_fee_accounting_out_of_scope` 拒绝。实际利息必须进入当前账本内精确且有效的利息收入分类对应账户。任何校验失败都保持完整操作前命名基线和逐项为零的正式、余额、报告、现金流、收入及对账效果。

## 11. 证据与对账

证据职责严格分离：

- 银行或钱包入账使用 `destination_asset_posting` 职责，只链接精确到账资产分录，证明来源实际包含的金额、账户、入账时间和起息时间。
- 借款协议或收据使用 `counterparty_lending_relationship` 职责，只链接借贷位置，支持稳定往来对象和借贷关系。
- 借出银行扣款使用 `funding_asset_posting` 职责，只链接借出交易中的实际资产 A 分录。

银行证据不证明行为、往来对象或本金、利息与费用拆分；协议或收据不证明资产 B 的银行入账。到账资产分录独立对账，应收与收入分录不适用金融账户对账。证据状态变化只改变对账状态，不改变交易、位置、余额或报告。

## 12. 来源、历史与幂等

来源记录保留观察时间、入账时间、起息时间、账户、金额、币种和不可变载荷摘要。候选历史依次保存待确认与已确认状态；位置历史、结算历史、版本和确认来源分别使用稳定 ID 并按顺序追加。正式发生时间使用明确确认的实际资金时间，来源和确认时间不互相覆盖。

相同借出请求、借出银行扣款来源、往来对象改名请求、手工收款请求、手工确认来源、手工到账来源、本金上限成功请求、导入入账来源、关系协议来源、候选确认、镜像合并请求或镜像来源重试时返回原稳定结果。每一种重试都有自己的命名完整基线、与基线逐字段相等的完整结果状态、返回的稳定实体 ID，以及独立保存的零重复实体计数和零正式效果计数；不得依赖共享汇总向量。重试不新增候选、位置、结算、组成、交易、分录、版本、历史、来源、证据或证据链接，也不重复现金流和收入。

后到镜像入账证据合并到已有到账资产分录。镜像完成状态只新增该来源、证据和合并链接；交易、版本、位置、结算、余额、报告与对账逐字段保持不变。

## 13. 完整状态与引用完整性

机器答案为借出完成、手工收款完成、导入待确认、导入确认、镜像完成和本金结清分别保存完整规范状态。每个状态包含带全部分录的交易、版本、位置及历史、结算及稳定组成、候选、确认来源、来源记录、证据、证据链接、余额、逐期报告和对账。

所有无效输入、导入缺失确认和本金超额操作都保存精确操作上下文、完整操作前命名基线，以及与基线逐字段相等的完整结果状态。引用完整性遍历全部规范状态、成功操作结果、失败操作结果、操作前基线和幂等重试状态，不只检查汇总实体注册表；它验证交易与当前版本、位置历史交易、结算与组成分录归属、候选来源、证据来源、证据职责目标和确认目标全部存在且类型正确。测试从期初开始累计重放借出完成、手工收款、导入确认、镜像完成和本金结清状态，逐币种验证平衡与精确余额，并从交易行为和结算组成独立推导逐期及累计报告。导入待确认状态必须与借出基线拥有相同正式交易、余额、报告和对账。

## 14. 范围边界

v1 不覆盖合同级借贷、应计利息、抵押品、外汇、豁免、往来对象合并、税务、非零结算费用的方向、账户与报告语义、超出明确组成金额的催收或费用生命周期，以及借入和还款的详细生命周期。这些内容不能从当前 fixture 推断为已实现行为。

禁止的隐式效果包括自动截断本金、跨越位置零点、分配到某笔借出、猜测组成拆分、按名称猜测往来对象、确认预计利息、建立清算分录、建立兜底收入，以及用关系证据冒充银行入账核验。

## 15. 验收标准

`RG-08` v1 只有同时满足以下条件才通过：

- 借出交易为应收 `+100.00`、资产 A `-100.00`，本金现金流出 `100.00`，消费、费用、收入和净资产变化为零。
- 收款交易为资产 B `+45.00`、应收 `-40.00`、利息收入 `-5.00`，剩余应收本金为 `60.00`。
- 收款期本金现金流入 `40.00`、利息现金流入 `5.00`、总现金流入 `45.00`、普通利息收入和净资产增加均为 `5.00`，消费为零。
- 预计或应计利息没有正式效果，只有实际收到的利息确认收入。
- 个人级位置使用稳定往来对象 ID，不分配到合同或某笔借出；改名零财务影响，合并不在范围内。
- 本金不得超过余额或跨零，超额整笔拒绝并等待明确处理，不自动截断或猜测其他事件。
- 导入在六组经济事实全部明确确认前保持待确认和零正式影响。
- 导入接收实体增量与零正式效果使用两个精确向量；费用必须显式为 `0.00`，负数和正数非零费用均原子拒绝。
- 银行入账、借贷关系和借出扣款使用类型明确且目标有效的证据职责，到账资产分录独立对账。
- 所有实体身份、来源、确认和历史不可变保留；镜像及全部请求、来源和证据重试不重复任何正式、报告或对账效果。
- 所有无效和不完整操作保持完整命名基线，全部正式及报告效果计数为零。
