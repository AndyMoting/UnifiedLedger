## 1. 证据模型

### 1.1 固定验收计划与两类证据

**本计划的固定面：** 三条跨切片流程使用同一个固定 Android 候选与同一份小型匿名初态夹具。候选身份至少记录提交、构建产物哈希与环境 profile。每条流程从夹具各自复现的初态开始；初态可重放，且不以另一条流程的写入结果作为起点。三条流程的正式账本前后读回分别记录。

**两类证据：**

- **本计划的强制证据**：三条流程、§3.1 的 Q3 朗读与 §3.3 的 Q5 规模读数。它们绑定固定候选与各自点名的夹具或载荷，必须在阶段收口前按本规格取得；历史读数不得替代。
- **历史单切片证据**：各切片已登记的证据。它按 §1.2 复用；其候选不必与固定候选相同，只要来源可追溯且差异不影响原断言。

**规模载荷分开：** §3.3 的 61k 搜索夹具与 10,000／10,001 行导入载荷是各自原向量的独立载荷，不与 §2 的小型流程夹具混同。

**证据记录：** 每条结果记录候选、夹具或载荷、环境、操作步骤、界面结果与正式账本读回。记录使用公开的合成值，不写入本机信息或私人事实。

### 1.2 单切片证据复用（Q1）

单切片证据满足以下两条时复用；否则补受影响项：

1. 来源可追溯：能定位到原切片规格、验收向量与证据记录；
2. 候选差异不影响原断言：界面、账务效果、失败语义或规模终点在原候选与固定候选之间没有改变原判据的作用。

历史证据的候选与固定候选可以不同；判断的是差异是否影响原断言，而不是候选是否相同。复用不改变原结论，也不把单切片证据升级为跨切片证据。受候选差异影响的项按本条补齐。

### 1.3 证据账

| 路线图维度 | 覆盖来源 | 复用与补证 |
| --- | --- | --- |
| 离线功能 | 三条跨切片流程（本计划强制）；各切片原验收向量（历史证据） | 流程按 §2 取得；历史向量按 §1.2 复用；流程未覆盖的切片内行为按原向量补证 |
| 正式账本效果 | 每条流程的正式账本前后读回：交易、分录、余额、报表、候选与状态计数 | 金额与计数用精确值；受候选差异影响的效果逐项补证 |
| 失败恢复 | 三条流程内的批级拒绝、同源候选另行入账被拒、超额退款阻止确认与零写入读回；其他失败语义按各切片原向量 | 流程内三条失败腿作为跨切片读回；其他失败按 §1.2 复用或补证 |
| 长账本可操作性 | §3.3 的 P8-02 V-8 渲染终点与 P8-04 V-7 设备边界读数（本计划强制）；原切片规模向量（历史证据） | Q5 两项按 §3.3 取得，不用历史读数替代；历史规模读数按 §1.2 复用，候选差异不影响终点时保留；不新增阈值 |
| 关键页面视觉 | P8-00 V-8 基线、各切片字号机与设备样本；P8-06 V-12（恢复后） | 按 §1.2 复用；不新增视觉判据 |
| 无障碍 | §3.1 的 P8-00／02／03 云端真实 TalkBack；P8-05 R2 例外；P8-06 V-12（恢复后） | 语义树只证明可达；真实朗读按 §3.1；R2 按 §3.2 记缺证 |

### 1.4 证据类型不得互相替代

- 设计批准、规格获批与阶段验收分别记录；本设计不判任何实现或验收结论。
- JVM／`app-ui` 测试、设备仪器化、font-scale 样本、云端 AVD 与真机是不同证据面；低一层不替代高一层。
- 搜索端口的返回时间不替代界面渲染完成；1,000 行读数不替代 10,000／10,001 行最大档。
- 无障碍语义树不替代真实 TalkBack 朗读；模拟器不替代真机。
- tracked 交付的落地证据是精确 PR head 的四项必过检查与合并树守卫；它们不替代上述运行时验收。

## 2. 三条跨切片流程（Q2）

以下三条是阶段收口的最小跨切片流程。每条从同一小型匿名初态夹具的独立初态开始，使用现有界面；证据绑定固定候选和夹具，记录界面结果与正式账本前后读回。单切片规模与无障碍证据仍按 §1.2 判定。

| 流程 | 通过判据 | 原判据来源 |
| --- | --- | --- |
| 导入 → 搜索 → 导出 | 在自填导入中先选表头错误的 XLSX，批级拒绝且正式账本不变；换正确文件审核确认，恰有一笔落账。用已确认的分类或日期筛选，详情与账本一致、原路返回。导出全账本，核对该交易对应行及精确金额，导出不改账本。 | P8-04 D-10、P8-02、P8-05 |
| 导入证据 → 对账 → 审计回看 | 从有资格的导入候选进入对账，绑定并确认既有真实分录。回到审核面能识别已用于对账；尝试用同源候选另行入账被拒。重进审计仍能定位原证据，活动链接一条，正式交易、分录与余额不变。 | P8-01a §2.4–2.7 |
| 手工退款 → 跨月报表 → 日明细 | 先填超额退款，阻止确认且零正式写入；改为合法金额，确认后按到账时刻新增一笔退款。核对原支出月不变、到账月与到账日反映同笔退款；日明细开详情后原路返回。 | P8-03、P8-06 |

流程中的界面呈现按实际观察判定；P8-01a V-10 的导航与呈现同样按实际观察判定。任一流程失败即阶段收口不成立，不用其他流程的通过抵消。

## 3. 补证与例外

### 3.1 真实 TalkBack 补证（Q3）

P8-00、P8-02、P8-03 在 P8 收尾批、宣布阶段收口前，用受管云端 AVD 在 1.3× 下补目标节点的真实 TalkBack 朗读。

- 逐目标记录 TalkBack 版本、焦点、朗读日志与截图；目标节点取各切片原验收向量点名的无障碍项。
- 语义树只证明可达，不证明朗读；金额逐项核对正负号、数值与币种。
- 旧切片结论与其披露保留，不因本轮补证改写。
- 依据：`D-305(c)`、`D-311` V-9、`D-313` V-14 与 `D-292` 已取得真实朗读的先例。
- P8-06 V-12 继续暂停，须另行明确恢复；P8-05 R2 按 §3.2 处理。

### 3.2 真机例外（Q4）

只有 P8-05 R1、R2 两项是 Q4 例外；任何其他缺证不得援引本条。

- R1（真机 Excel/WPS 打开）与 R2（横幅播报与进度朗读）保留[设备证据登记](../specs/2026-11-15-p8-05-readable-export-device-evidence-registry.md)的真机要求。在所需真机证据取得前，两项记缺证、不记 PASS；取得合格真机证据后，按原向量闭合。
- 内容解析、语义树与模拟器不替代真机；真机操作另需授权。
- 两项仅在 `D-363` 与 `docs/ROADMAP.md` 同批落地、且其余收口证据满足后，才作为不阻断阶段收口的例外；缺证本身仍登记。

### 3.3 规模补证（Q5）

在固定候选上由云端补两组读数，沿用原判据，不新增耗时阈值：

1. **P8-02 V-8**：61k 交易夹具、默认窗与固定条件组查询的「首屏渲染完成」终点。端口返回不替代渲染。
2. **P8-04 V-7**：自填导入 10,000／10,001 行的设备边界读数。1,000 行不替代最大档。

每组记录候选、夹具、环境、可观察终点及结果。这两组载荷与 §2 的小型流程夹具分开，且均为本计划强制证据，不由历史读数替代。依据：`D-311` 第 2 条与 [P8-04 验收向量](../specs/2026-11-14-p8-04-self-entry-import-design.md#5-验收向量)。

- **P8-04 V-6**：确认腿按 §2 的第一条流程取证后逐项核对；模板写出失败的 CreateDocument 失败类型化仍按原向量独立取证，不由该流程替代。pending 期间的诚实可用性文案与 i4 翻转条件沿用原判据。
- **P8-01a V-10**：导航和呈现按实际观察判定，不以端口或语义树替代。
- **历史阶段 7 例外**：保持原结论；`P706-A06` 真实掉电腿仍为需真机的验收例外，不转 PASS。
- 各切片已登记的残余与披露继续有效，不因阶段验收被清除或升级。

## 6. 阶段收口

阶段收口按以下清单逐项成立；任一未成立即不收口：

1. 固定候选上的三条跨切片流程全部通过。
2. §1.3 的六类强制证据均满足；各切片原验收向量按 §1.2 复用或补证，没有未登记的缺证。
3. §3.1 的 P8-00／02／03 云端真实 TalkBack 补证完成；旧披露保留。
4. §3.3 的两组规模读数已记录，且未引入新阈值。
5. P8-06 V-12 与批 7 保持暂停；恢复后按原条件闭合。
6. §3.2 的 R1/R2 在所需真机证据取得前记缺证、不记 PASS；取得合格真机证据后按原向量闭合。两项仅在 `D-363` 与 `docs/ROADMAP.md` 同批落地且其余证据满足时，作为不阻断收口的例外。
7. 凡有 tracked 交付，以该 PR 精确 head 的四项必过检查 `Kotlin tests`／`Android compile`／`Python tests`／`Trace scan` 与合并树守卫「落地树 == PR 树」为落地证据。
8. 阶段验收以独立决定记录；设计批准、规格获批与阶段验收不合并为同一结论。

本设计批自身的落地证据同样以该 PR 精确 head 的四项检查与合并树守卫为准；本文不声称已取得。
