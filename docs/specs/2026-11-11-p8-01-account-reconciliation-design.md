## 1. 起点：本规格要修的四条现状

1. **确认面只认转账腿**：写路径完整性谓词是 `COALESCE(tx.canonical_kind, tx.kind) = 'ACCOUNT_TRANSFER'`（`Ledger.sq:9027-9039`），其余类型返回 `P408_POSTING_NOT_ELIGIBLE`。
2. **matcher 完备但零生产消费者**：`P408Matcher.kt:119-182` 按 O-1 五字段同判、O-2 ±2 自然日成候选；多命中 `AMBIGUOUS`、无唯一命中 `UNRESOLVED`，从不自行选择（O-3）。全仓 `P408Matcher(` 的调用点都在测试里。
3. **读面资格使「待对账」不可达**：`isReconciliationEligible`（`LedgerEntryReadModels.kt:102-107`）要求 rg03 标记或有证据链或已有对账行；`posting_reconciliation` 的产品行只由 v23 迁移种子与确认/修正写入，**v23 之后新建的手工转账腿没有行**，因此详情屏恒显示「无对账资格」。五态里的 `PENDING` 在产品中不可达。
4. **没有账户范围读，也没有「为什么匹配」读模型**：`P408ReconciliationReadPort` 只有 ledger 级一个方法（`P408Reconciliation.kt:160-162`）；`reconciliation_request_snapshot` 持有 `match_basis`/`window_days`/`natural_day_distance`/`human_decision`，但唯一读者是测试专用查询。

## 2. 首片冻结的行为

### 2.1 资格派生（修订 `D-145` §3.2.1 的读面）

读面资格改为：**rg03 语义行的标记优先（`false` 胜出，费用腿继续排除）；没有 rg03 行时，凭「该分录所属账户是用户持有的真实资产或负债账户」判定**。真实资产/负债分录没有对账行时，读作 `PENDING`（待对账）。

这条只改**呈现派生**，不改写入：历史分录、金额、余额、版本、报表零变化。非真实账户分录（费用/收入/隐藏系统账户）仍为「无对账资格」，且 `null` 仍表示「不显示任何对账状态」。

写面资格本片不动——`confirmLink` 继续只接受 `ACCOUNT_TRANSFER` 腿。**状态与动作分开呈现**：一条腿可以如实是「待对账」而在当前版本里「暂不支持在应用内核对」。

### 2.2 入口（两处，同一用例）

- **入口 A（账户视角）**：账户流水屏新增「账户对账」动作，进入该账户的对账队列。
- **入口 B（候选视角）**：导入审核的候选行在未链接时提供「用于核对既有分录」，进入同一屏的**证据聚焦模式**（以该候选的证据为锚，列候选分录）。

两个入口共用同一确认用例与同一呈现组件；区别只在初始查询方向。

### 2.3 队列

队列 = 该账户当前有效、真实资产/负债的分录，按 `occurred_at DESC, posting_id ASC` 键集分页（页大小 100）。每行呈现：日期、备注或交易类型、该腿精确带符号金额与币种、五态状态。

- 队列**只列未核对**（`PENDING`/`PARTIAL`/`DIFFERENCE`/`MISSING`）与已核对的最近一页；已核对默认折叠。
- 汇总按 `(币种, 状态)` 聚合：**已核对合计 / 未核对合计 / 条数**。禁止呈现「账户余额 − 区间明细合计」的差额——该算法已被竞品语料自我否定（`UL_ABSORB_2026-11-03.md:106` E2），且余额不得由对账反推。
- 聚合读失败或金额溢出时显式失败并保留已加载行，不以零掩盖。

### 2.4 候选证据与匹配依据

选中一条待对账腿后，应用层以冻结的 matcher 计算候选：`match(evidence, [该腿所属账户在当前版本内、±2 自然日窗内的真实资产/负债分录])`，只取该腿出现在候选集内的结果。

- `PROPOSED_MATCH` → 展示唯一候选，可直接确认。
- `AMBIGUOUS` → 列出全部候选与各自自然日距离，要求用户**明确选择**其中一条；用户选择即是 O-3 的人工决定。
- `UNRESOLVED` → 呈现成因（`no_unique_funding_candidate` / `source_time_unresolved` / `funding_facts_unresolved` 原样转述），该腿保持待对账，**零写入**。
- 证据侧只取 `READY` 投影（`P408ProjectionState.READY`）且尚无活动链接的证据；`REJECTED` 投影不进候选。

匹配依据只呈现 matcher 给出的五字段（`amount`/`currency`/`direction`/`account`/`occurred_at_window`）与自然日距离；`confidence` 只有 `EXACT` 一个值，界面不得暗示评分或排序。

### 2.5 确认

确认是两步：先看清四要素（外部证据、证据职责、匹配依据、人工决定），再点确认。

- 请求由应用层构造 `P408ConfirmLinkRequest`，`basisVersion = 2`、`windowDays = 2`、`naturalDayDistance` 取 matcher 输出、`matchBasis` 取冻结五元组、`confirmedAt` 取注入时钟、身份由账本既有发号端口给出。**界面不得自造 basis 或距离**。
- 首片职责只有 `REAL_ACCOUNT_POSTING`；`DESTINATION_ASSET_POSTING` 指向的退款到账腿不属于 `ACCOUNT_TRANSFER`，写路径本片不接受，故不呈现确认动作。
- 结果按类型化三分支：`Accepted` → 刷新队列与详情；`NoChange`（同 requestId 同指纹重放）→ 视为成功且不重复写；`Rejected(code)` → 原样呈现 code 对应的可读文案，零写入。
- **结果未知**（进程中断、无回执）按既有惯例处理：界面提示「结果未知，重新进入核对」，重进后以权威回读判定；同一 requestId 重试必须命中 `NoChange` 或原回执。

### 2.6 审计回看

对已核对腿展示：证据来源（哪一次导入、哪条来源行）、证据职责、匹配依据五字段与自然日距离、人工决定时间，以及状态历史（`confirmed`/`posting_replaced`/`corrected` 与序号）。

历史与依据**只读**；没有任何界面路径可以改写或删除既有链接。

### 2.7 双记账防护

证据被链接到既有分录后，同一证据不得再产生第二笔正式交易：

- 导入审核列表不落新状态，由 `evidence_link` 是否存在**派生**显示「已用于核对既有分录」。
- 导入确认路径新增前置守卫：候选所属证据已有活动链接时类型化拒绝 `IMPORT_EVIDENCE_ALREADY_RECONCILED`，零正式写入、零候选状态变化。
- 同一证据再次确认对账由既有 `P408_EVIDENCE_ALREADY_LINKED` 拒绝；同一分录同职责再次链接由 `P408_POSTING_RESPONSIBILITY_ALREADY_LINKED` 拒绝。

## 3. 只读契约（新增查询与端口，零 DDL）

| 用途 | 形态 | 说明 |

| 队列 | 具名查询 + 端口方法 | 账户 + 键集游标；返回该腿当前状态、是否有活动链接、交易类型、账户真身标记 |

## 5. 范围边界

**本片不做**（不得据本规格实施）：写路径扩面到非 `ACCOUNT_TRANSFER` 分录（属 P8-01b，需 v36→v37 回填与谓词放宽）；`DIFFERENCE`/`MISSING` 的用户可写声明（今天只有修正路径能写这两个状态，首片只解释成因）；时间范围选择器；批量确认；跨账户或跨币种匹配；`PARTIAL` 的写入（产品中无写入者，保持只读呈现）。

**不变量**：正式金额、分录、余额、报表、版本、作废恢复零变化；对账状态只描述核验程度；不伪造交易补平差额；不把通道总额或余额差额当作对账结论。

**P8-01b 的登记范围**（本规格不实施）：`selectP408PostingIntegrity` 放宽为真实资产/负债分录、`posting_reconciliation` 回填迁移、证据职责在非转账类型上的裁定、以及届时对读面的统一。
