# RG-07 退款设计

## 1. 目的

本设计冻结公开匿名黄金场景 `RG-07` v1 的退款业务答案。它验证退款状态零财务影响、实际到账独立入账、原分类继承、到账期报告、累计退款上限、导入确认、证据职责、分录级对账、完整来源历史、镜像合并和幂等结果。

本设计只规定可观察的账务、报告和状态行为，不固定数据库、界面或平台实现。跨币种、负债或商户储值到账、拒付或超额补偿、多分类或合并购买分配、手续费退款、分阶段付款取消或退款，以及账目修正不属于 v1。

## 2. 固定数据与独立基线

场景使用完全合成的数据：

| 项目 | 固定值 |
| --- | --- |
| 场景 ID | `RG-07` |
| 场景级别 | `core_required` |
| 规则版本 | `1` |
| 时区 | `Asia/Shanghai` |
| 币种与精度 | `CNY`，两位小数 |
| 原付款账户 | `asset-bank-a`，资产账户 A |
| 退款到账账户 | `asset-wallet-b`，资产账户 B |
| 二级支出分类 | `expense-category-daily`，生活 > 日常用品 |
| 隐藏费用账户 | `expense-account-daily` |
| 原支出 | `120.00 CNY`，`2026-01-10T12:00:00+08:00` |
| 部分退款到账 | `30.00 CNY`，`2026-02-02T15:20:00+08:00` |

手工路径与导入路径分别从相同独立基线运行，不互相累计。基线通过平衡期初交易建立资产 A `1000.00 CNY`、资产 B `200.00 CNY` 和期初权益 `-1200.00 CNY`；测试不得直接覆盖余额。

## 3. 原支出

用户明确确认原支出后创建一笔平衡交易：

| 分录账户 | 金额 |
| --- | ---: |
| 日常用品费用 | `+120.00 CNY` |
| 资产账户 A | `-120.00 CNY` |

原支出后资产 A 为 `880.00`，资产 B 仍为 `200.00`，费用累计为 `120.00`。原付款资产分录已由自己的银行证据核对。原交易、版本、分录、分类、发生时间和对账状态均使用稳定身份，并在后续退款中保持不变。

## 4. 退款状态零影响

退款在 `2026-01-20` 申请、`2026-01-21` 获批并于 `2026-01-23` 进入处理中。系统建立稳定 `refund` 关系，关联原交易并依次追加 `requested`、`approved` 与 `processing` 历史。

这些状态只记录业务事实。每次状态变化的正式影响计数均为零，不创建交易、分录或版本，不改变资产 A、资产 B、费用、消费、现金流、收入、净资产或对账。商户通知可以支持关系和处理状态，但不能证明资产 B 已经到账。

## 5. 实际到账交易

用户在 `2026-02-02T18:00:00+08:00` 明确确认 `30.00 CNY` 已于当天 `15:20` 到达资产 B。该确认可以在没有外部账户来源时建立到账事实，并创建一笔与原支出分开的平衡退款交易：

| 分录账户 | 金额 |
| --- | ---: |
| 资产账户 B | `+30.00 CNY` |
| 原日常用品费用 | `-30.00 CNY` |

到账后资产 A 仍为 `880.00`，资产 B 为 `230.00`，累计费用为 `90.00`。退款交易链接原交易，但不替代原版本、不修改原发生日期，也不重置原付款分录的对账结果。

如果同一手工请求提供金额、分类、到账账户和到账时间但 `arrival_confirmed` 为否，系统保持待确认。该操作保存完整操作上下文、操作前命名基线和与基线逐字段相等的结果状态，所有候选、关系、交易、分录、版本、历史、来源、证据、余额、报告和对账效果计数均为零。

## 6. 报告与分类

原期间 `2026-01` 保持消费 `120.00`、现金流出 `120.00`、退款现金流入 `0.00`、普通收入 `0.00`、净资产变化 `-120.00`。到账期间 `2026-02` 记录消费 `-30.00`、退款现金流入 `30.00`、普通收入 `0.00`、净资产变化 `+30.00`。累计消费成为 `90.00`，累计普通收入仍为零。

退款严格继承原交易的精确二级支出分类和对应费用账户。用户不能只为退款选择其他分类；如果原交易分类错误，必须先通过版本替代修正原交易。多分类原支出如何分配退款不属于 v1。

## 7. 累计退款上限

同币种有效关联退款按原交易累计。原已确认可退费用为 `120.00`，已有一笔独立有效退款 `30.00` 时，剩余可退金额严格为 `90.00`；在 `2026-02-10T10:00:00+08:00` 再确认另一笔独立退款 `90.00` 可以接受，累计恰为 `120.00`。第二笔使用不同请求、关系、交易、版本和分录 ID，继承同一精确二级分类。重放期初、原支出和两笔退款后，资产 A 为 `880.00`、资产 B 为 `320.00`、费用余额为 `0.00`；`2026-02-02` 消费 `-30.00`、`2026-02-10` 消费 `-90.00`，二月消费及退款现金流入分别为 `-120.00` 与 `120.00`，累计消费为零。

若同一基线下尝试把到账 `100.00` 全部分配给原交易，系统整体拒绝，不自动接受其中 `90.00`。已分配金额保持 `0.00`，`100.00` 全额继续处于待明确分类状态，不能静默变成普通收入、补偿、其他事件或隐藏平衡分录。并发或重试后的有效累计也必须执行同一上限。

## 8. 到账账户、证据与对账

到账账户可以不同于原付款账户，但必须由银行或钱包入账证据支持，或由用户明确确认。系统不得根据原支付路径、商户、金额或时间猜测。v1 只接受已知、由用户持有的真实资产账户。

证据职责严格分离：

- 商户退款通知使用 `refund_relationship` 职责链接退款关系，只证明关系或状态，不核对资产 B。
- 银行或钱包入账使用 `destination_asset_posting` 职责链接退款交易的资产 B 分录，只核对该精确分录。导入账户入账时不得再为该来源建立 `refund_relationship` 链接。

原付款资产 A 的分录保持原有已核对状态。资产 B 退款分录在手工确认后可以仍待对账，到账证据到达后独立成为已核对；费用分录不适用金融对账。导入账户入账的退款关系由用户明确确认来源单独建立。只有其他确实同时证明关系和到账的复合来源，才建立两个职责及目标都明确的证据链接，不能用一个含糊链接代替。

## 9. 时间与来源历史

申请时间、批准时间、处理方报告时间、来源观察时间、银行入账时间、起息时间、用户确认时间和实际到账时间分别保存，不相互覆盖。正式退款发生时间和默认统计时间使用明确确认的实际到账时间。

关系状态历史、候选历史和版本历史均使用稳定 ID 并按顺序保存。来源原始载荷以不可变引用和摘要保留；人工确认与来源建议冲突时两者都存在于来源链，正式结果只由明确确认决定。

## 10. 导入与确认

导入资产 B 的 `30.00 CNY` 入账先创建 `pending_confirmation` 候选。即使来源带有金额、币种、账户、入账时间和较高置信度，也不能自动创建正式退款。

候选必须逐项明确确认：原交易、原精确二级分类与 `30.00` 分配、到账账户 B，以及到账事实与时间。任何一项缺失都保持待确认，交易、分录、关系、版本、消费、现金流和对账影响为零。四项全部确认后才创建与手工路径经济结果相同的独立退款交易。银行或钱包来源只链接精确到账资产分录；退款关系由该次用户确认的不可变来源记录建立，不把银行或钱包来源提升为关系证据。

## 11. 校验与冻结失败

金额必须是正的两位精确十进制 `CNY`，原交易必须是有效且已确认的支出，到账账户必须是已知的自有真实资产账户，分类必须是原交易现有的精确二级支出分类，金额不得超过剩余可退费用。零数、负数、跨币种、无效原交易、未知或非自有账户、负债或商户储值账户、缺失或不同分类、超出上限，以及缺少明确原交易或到账账户确认均拒绝。

每次失败都保存精确操作上下文、完整操作前命名基线，以及与该基线逐字段相等的完整结果状态。候选、关系、交易、分录、版本、历史、来源、证据、余额、报告、对账、消费和现金流的效果计数逐项为零。导入确认缺失、手工未确认到账和累计超限执行同一契约。系统不得猜测原交易、分类、账户或关系，也不得为通过校验建立隐藏补平。

## 12. 幂等与完整状态

相同原支出请求、退款状态请求、商户通知、手工到账确认、银行或钱包入账证据、导入来源、候选确认、复合来源和镜像来源重试时返回原稳定结果。重试不新增候选、关系、交易、分录、版本、历史、来源记录或证据链接，也不重复消费与现金流。

机器答案保存手工路径与导入路径的完整规范状态，包括带全部分录的交易、版本、带全部时间与历史的关系、候选与确认来源、来源记录、证据和证据链接、余额、逐期报告及对账。镜像合并后的状态保留新增来源与合并链接；随后重试返回的完整规范状态必须逐字段相等。

## 13. 机器可比较契约

机器答案使用 `schema_version: 1`。所有金额是两位小数十进制字符串，所有正式分录明确使用 `CNY`，所有请求、来源、候选、关系、历史、交易、版本、分录、证据和匹配均使用稳定 ID。

共享校验器负责场景信封、精确金额、稳定 ID、逐币种平衡、分录唯一性和余额重放。实体注册表进一步验证每个来源、证据、关系、交易和分录目标存在且类型正确，并验证证据职责只能指向对应类型。针对性测试冻结原交易与退款独立性、状态零影响、到账期报告、分类继承、累计上限、到账账户确认、证据职责、独立对账、时间与来源历史、导入确认、镜像合并、完整规范状态、幂等、校验原因和范围边界。

## 14. 验收标准

`RG-07` v1 只有同时满足以下条件才通过：

- 原支出与退款分别平衡，退款后资产 A 为 `880.00`、资产 B 为 `230.00`、累计费用为 `90.00`。
- 申请、批准和处理中状态严格零正式影响，只有明确确认实际到账才创建退款交易。
- 原期间保持消费及现金流出 `120.00`；到账期间消费 `-30.00`、退款现金流入 `30.00`、普通收入 `0.00`、净资产增加 `30.00`，累计消费为 `90.00`。
- 退款继承原精确二级支出分类，原分类错误时先修正原版本，不为退款猜测或覆盖分类。
- 有效关联退款累计不超过原可退费用，超额分配原子拒绝且未分配金额不被静默分类。
- 到账账户可以不同但必须有证据或明确确认；商户通知与账户入账使用独立证据职责，到账分录与原付款分录独立对账。
- 导入在原交易、分类分配、到账账户和到账事实全部明确确认前保持待确认与零影响。
- 全部时间、来源、版本和状态历史不可变保留；镜像、重复来源和所有重试不重复任何正式、报告或对账效果。
- 所有无效输入保持完整基线，所有范围外业务未被提前实现。
