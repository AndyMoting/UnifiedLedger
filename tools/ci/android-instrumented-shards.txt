# Case authority stays tools/ci/android-instrumented-inventory.txt: this file
# only splits its 17 classes across 2 shards, union 61 cases, no duplicates.
# `tools/ci/android-instrumented-cloud.py check` proves that partition; any
# class added to, removed from, or renamed in the inventory must be reflected
# here or the producer job fails before a device boots.
# Placement follows the case count per class, balanced at 34/27 (shard 1:
# 8/6/7/1/5/6/1 = 34 over AndroidRestoreDocumentSize 8 + AndroidRestoreRecovery 6
# + CcbBillParserAndroid 7 + BackupExportSafMidWrite 1 +
# P801AccountReconciliationChain 5 + P805ReadableExportDeviceChain 6 +

# AndroidRestoreConfirmSwitch 1 + AndroidRestoreSourcePort 3 +
# AndroidStartupFailClosed 4 + P802SearchDeviceTiming 1 + SelfEntry 4 +
# ImportReviewPaging 1 + P806ReportDeviceTiming 1). The
# P8-02 V-8 and P8-06 V-14 timing cases ride shard 2 and cost nothing there
# unless the dispatch passes ul.p802.timing=1 / ul.p806.timing=1. The P8-05
# device-chain class rides shard 1
# beside the mid-write rig (same shard-1 placement family; no dedicated rig
# isolation is needed because the class fills no filesystem — its
# write-failure leg reuses the D-288 pipe rig).
# P807Q2ImportSearchExport rides shard 1 and is the manifest's FIRST case: it
# seeds the app's OWN stable storage (the shared Q2 seed) before launching
# MainActivity, so its seed guard requires that no earlier case in that shard
# process opened the ledger. The shard plan preserves inventory order, so the
# case executes first; that is why it is listed first in the inventory.
# ImportReviewPaging rides shard 2 on purpose: it publishes the app's own ledger
# file before launching MainActivity, so no case ordered before it in that
# shard's process may have opened the app — none of shard 2's earlier classes
# launch an activity (the app-launching classes ride shard 1).
